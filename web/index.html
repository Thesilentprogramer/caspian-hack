Install on this laptop

Mapping is process-local. There is no public hosted MCP. Clone the repo, sync the env, reload Cursor. Do not run privacy-guard-mcp in a normal terminal — it speaks stdio JSON-RPC. Optional private HTTP on loopback needs MCP_AUTH_TOKEN (not the Caspian key).

  1. Python env 
    uv sync --extra dev
cp .env.example .env
  2. Cursor MCP This project already ships .cursor/mcp.json: 
    {
  "mcpServers": {
    "privacy-guard": {
      "command": "uv",
      "args": ["run", "privacy-guard-mcp"]
    }
  }
}
    Reload MCP servers. You should see sanitize, restore, redaction_report, list_inbox, get_thread, and brief_status.
  3. Claude Desktop (optional) Point uv at your clone. Replace the directory with the real path: 
    {
  "mcpServers": {
    "privacy-guard": {
      "command": "uv",
      "args": ["--directory", "/path/to/caspian-hack", "run", "privacy-guard-mcp"]
    }
  }
}
  4. Channel Adapter 
    uv run privacy-guard-agent
    Slack + Email always. Telegram if TELEGRAM_BOT_TOKEN is set (bot @CaspianPrivacyGuardBot). Live counts: http://127.0.0.1:8787 — never values.

Use the three tools

Before any model sees a Channel Message that may contain secrets:

  1. sanitize Returns Safe Text and a Mapping Id. Work only on those.
  2. redaction_report Counts unique Placeholders per Category, e.g. {"IP_ADDRESS": 1, "API_KEY": 1}. Never real values.
  3. restore Puts values back using the Mapping Id, right before the human sees the reply.
  4. list_inbox / get_thread / brief_status Pull Caspian conversations, Sanitize, return Safe Text plus a Mapping Id and counts. The host model writes the briefing. No Completer inside the MCP. 
sanitize("having trouble connecting to 192.168.1.105 with key sk_live_abc123")
→ safe_text with [IP_ADDRESS_…] [API_KEY_…]
→ redaction_report(mapping_id)
→ restore before the reply

Honest limits

  • Person and org names are best-effort NER. They will miss edge cases.
  • The Mapping is in-memory. Restart the process and it is gone.
  • Text only — no attachments, no OCR.
  • This is Fernet (AES-128-CBC + HMAC), not a zero-knowledge proof.
